## 这是个啥

打游戏的时候，总有一些时刻值得来点声音：

- 队友刚拿一个人头就开始吹"这波我带飞" → 该来一句**《恭喜爹可以称帝了》**
- 稳赢的团战被翻盘 → 该来一句**《煮熟的鸭子飞走了》**
- 你被抓了在喊"救命" → 该来一句**《冲我来了》**
- 有人死不承认是自己送的头 → 该来一句**《万万没有此事啊》**

**AutoMeme Studio 就是干这个的。**

它常驻后台，听着你和队友的开黑语音、时不时瞄一眼游戏画面，
由大模型判断"现在这个时刻值不值得来一句"，值得就放，不值得就闭嘴。

> 它的原则是 **宁缺毋滥** —— 平时装死，出手必中。
> 毕竟《不要愤怒，愤怒会降低你的智慧》，一个没眼力见的音效播放器只会让人红温。

## 老夫这就来看看

### 🎧 听懂你们在说什么

| 通道 | 采集方式 | 用途 |
| :--- | :--- | :--- |
| **麦克风** | `sounddevice` 16kHz 直采 | 识别你自己说的话 |
| **扬声器回环** | WASAPI Loopback | 识别队友语音、Discord / QQ / 游戏内台词 |

两路完全独立，各自的设备和增益都能单独调。
扬声器通道还带**回声自闭环保护** —— 自己放出来的音效不会被当成队友说话而反复触发。

语音识别用的是 **SenseVoice-Small**，本地离线跑，中英双语，不联网、不上传。

### 👀 看懂画面里发生了什么

两种手段，按需开启：

- **本地 OCR**（零成本）：识别屏幕上的「阵亡」「胜利」「任务失败」等关键词
- **多模态视觉**：定期截图或按 `F9` 手动截图，交给视觉模型判断战局

> 图片是按数量计费的，所以这里做了**动静门控** —— 画面没变化就不抓、不发送。
> 毕竟《大凡正人君子其肉都太酸》，能省的地方就得省。

### 🧠 让大模型来当那个损友

由大模型结合上下文判断该不该接梗、接哪一句。
也能接 DeepSeek / Gemini / 任何 OpenAI 兼容接口，或者干脆断网用内置规则引擎。

## 核心设计：两段式漏斗

这是整个项目省 Token 的关键。

**问题**：如果每次都把全部 50 个音效的完整描述发给大模型，
光音效清单就要三千多字，一次闲聊也得花这么多。

**解法**：先缩小范围，再让大模型裁决。

```
第 ① 段  本地候选筛选（不花一分 Token）
         从上下文里筛出最相关的 3~5 个音效

第 ② 段  大模型裁决（只送这几个候选）
         把候选清单 + 对话上下文发给大模型

实测：单次请求从 4062 字压到 675 字，省约 83%
```

候选怎么筛？两种方式，设置页里能切换：

| 方式 | 原理 | 适合谁 |
| :--- | :--- | :--- |
| **关键词匹配**（默认） | 用预置词表做字面比对 | 想开箱即用、完全离线 |
| **语义向量** | 把话和音效描述都转成向量，按意思相近度召回 | 有 embedding 服务、想追求召回率 |

> **关于语义向量的实话**：它确实能识别同义不同词（说"打得漂亮"也能匹配到"打赢"），
> 但**必须配一个真实的 embedding 服务**（本地 Ollama 或官方 API）。
> 如果服务不可用，它会**自动退回关键词匹配**，不会让功能挂掉。
>
> 代码里还写了个「本地哈希向量」兜底，但实测它只能算字面重合度、
> 一样解决不了同义词问题（"打得漂亮" vs "打赢" 相似度是 0），
> 所以**默认关闭** —— 与其拿一个更差的方案糊弄你，不如直接告诉你需要配服务。

### 视觉模型可以独立配置

```
决策大脑（理解对话、挑音效）→ 随便什么模型都行
视觉模型（看一眼画面、出一句话）→ 建议用最小最便宜的那个
```

把高频的看图任务挪到独立渠道，主模型的额度能省下一大截。

> **一个踩过的坑**：官方 Gemini 按图像分块计费，384×384 的图只要约 258 tokens；
> 但**部分第三方反代是按 base64 字符数折算的**，那样同一张图可能要上千 tokens。
> 如果你的渠道是后者，降分辨率几乎没用，得把看图任务整个挪走。

## 走着

### 1. 装依赖

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows
pip install -r requirements.txt
```

> **注意**：`PyAudioWPatch` 和 `sherpa-onnx` 建议用 Python 3.8 ~ 3.11。

### 2. 下载离线识别模型

```bash
python download_models.py
```

会下载约 155MB：

- **SenseVoice-Small** — 中英双语语音识别
- **Silero VAD** — 判断"有人在说话"还是"只是环境噪音"

### 3. 配置接口

```bash
copy config.example.json config.json
```

编辑 `config.json`，填上你的接口：

```json
{
  "api": {
    "base_url": "https://api.deepseek.com/v1",
    "api_key": "sk-你的密钥",
    "model": "deepseek-chat"
  }
}
```

**不想花钱？** 不填 Key 就会自动用内置规则引擎，零成本零延迟，只是没大模型那么会看眼色。

### 4. 启动

双击 `启动GUI.bat`，或者：

```bash
python gui.py
```

也可以无界面跑（适合服务器 / 调试）：

```bash
python main.py --check    # 先自检配置、模型、接口是否就绪
python main.py            # 直接跑
```

## 这就不奇怪了

**Q：识别不准 / 完全没反应？**

先看「控制台」的音量条跳不跳。不跳就是设备选错了，在下拉框里换成真正在发声的那个。
专业声卡（比如 RODE）输出电平偏低，把增益拉到 3.5x 以上试试。

**Q：Token 花得飞快？**

按影响从大到小排查：

1. **图片开销** —— 带图决策的大头。降分辨率到 256/384，或者把视觉任务挪到独立模型
   （如果你的渠道按 base64 体积计费，降分辨率没用，必须挪走）
2. **召回引擎** —— 用语义向量的话，每次召回会多一次 embedding 请求
3. **触发灵敏度** —— 调「保守」，候选为空时就不会发起远程请求
4. **截图频率** —— 自动巡帧间隔调大（3~6 秒足够了）

**Q：缓存命中率一直是 0%？**

有些渠道压根不在响应里返回缓存字段，属于接口限制，不是你的问题。

**Q：该触发的时候不触发？**

三步排查：

1. 把「触发灵敏度」调到**激进** —— 如果好了，说明是门槛定太高
2. 把「候选数量上限」调到 8 —— 如果好了，说明是漏斗把正确答案筛掉了
3. 如果还是不行，说明关键词表覆盖不够：
   - 短期：在音效库里给那个音效补上触发描述
   - 长期：改用**语义向量**召回

**Q：能《接着奏乐接着舞》吗？**

可以。但它得判断出你正处于"优势巨大继续浪"的状态，而不是无脑乱放。
如果它判断错了，把灵敏度调低一点。
